# Этап 7. Финальная приёмка и README

**Статус: Черновик — ожидает согласования.** Подготовлен 27 ноября 2026.

## Результат и объём

README ориентирован на проверяющего, который открывает развёрнутое приложение.
Вверху — ссылка на демо, назначение приложения, короткий сценарий и объяснение
результатов. Ниже — схема интеграции, фактические проверки и ограничения.
В конце — компактный локальный запуск, конфигурация и команды проверки.
История этапов и эксплуатационные инструкции остаются в документации проекта.
Изменения интерфейса обсуждаются отдельно. Для этого объёма достаточно Markdown
и текущего приложения на Fly.io. Новые зависимости не требуются.

## Сценарий проверяющего

1. Открыть публичное демо, зарегистрировать тестовый аккаунт, перейти в кабинет.
2. Нажать «Подтвердить личность» и пройти WebSDK на уровне `id-and-liveness`
   с официальным Sandbox-шаблоном и шагом Selfie.
3. Вернуться в кабинет и увидеть сохранённый результат. При одобрении главная
   открывает котика. RETRY предлагает перейти к исправлению в кабинете.
   FINAL закрывает повторную подачу в рамках текущего решения.
4. После выхода и повторного входа проверить сохранение доступа. Во второй
   сессии без одобрения проверить отказ по тому же адресу изображения.

## Данные и интеграция

В сценарии используются тестовые аккаунты и официальные документы Sumsub.
README объясняет, что backend выдаёт токен для аккаунта из сессии, а доступ
к изображению определяется по результату подписанного webhook, сохранённому
в SQLite. В документации достаточно названий переменных и способов настройки:
секреты, документы, селфи и данные тестовых аккаунтов остаются вне Git.

## Последовательность

1. Зафиксировать фактические результаты v2. Пользователь подтвердил три
   исхода Sandbox с Selfie, сохранение доступа для одобренного аккаунта после
   повторного входа и отказ для неодобренных. Повторная подача после RETRY
   считается дополнительным сценарием по решению пользователя от 27 ноября.
2. Учесть отчёт о живой проверке токена. Для её подтверждения нужен повторный
   `POST /account/verification/token` с 200 при продолжении той же открытой
   проверки и сохранение того же профиля. До подтверждения в README указать,
   что обновление проверено на имитации. Выполненный пользовательский прогон
   можно использовать как подтверждение соответствующих критериев.
3. Переписать README вокруг пользовательского сценария. Оставить проверяемое
   описание архитектуры, локальные команды и имена настроек. Для эксплуатации,
   истории и подробных прогонов сослаться на существующие материалы в `project/`.
4. Сверить локальные команды с приложением, проверить ссылки и публичный
   `/healthz`. Если состояние или адрес демо изменятся, актуализировать README.

  ссылка на подходящие Sandbox-материалы Sumsub.

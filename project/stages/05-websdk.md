# Этап 5. Подключение Sumsub WebSDK в личном кабинете

**Статус: Согласован.** 26 ноября 2026 пользователь подтвердил план словами «Подтверждаю план». Приняты пункты 1–5: подготовка Sandbox, привязка аккаунта, серверная выдача токена, виджет в кабинете и проверки.

**Уточнение 26 ноября 2026.** Пользователь поручил реализовать основной код с локальными тестами и имитациями; реальные сценарии виджета проверить позже. Код подготовлен, статус этапа остаётся «Согласован» до Sandbox-приёмки.

**Результат.** Вошедший пользователь нажимает «Подтвердить личность» в кабинете и проходит шаги Sandbox внутри страницы. Получение решения через webhook, сохранение результата и открытие мема относятся к этапу 6. Деплой выполняется по отдельному запросу.

1. **Подготовить Sandbox.** Подтвердить разрешение на корпоративный Sandbox либо использовать отдельный. Уточнить точное имя и шаги Individual verification level. Sandbox App Token и Secret Key передать приложению через серверное окружение. В README указать только имена переменных.
2. **Связать аккаунты.** При первом запросе сохранить в SQLite случайный уникальный внешний ID пользователя. Использовать его повторно при входе и обновлении токена. Такая привязка работает и для существующих аккаунтов, а после пересоздания базы новый пользователь с тем же логином получит другой ID.
3. **Выдать SDK-токен.** Добавить защищённый POST-маршрут. Сервер определяет пользователя по действующей сессии, берёт level из конфигурации, подписывает запрос к Sumsub через HMAC-SHA256 и возвращает краткоживущий SDK-токен с Cache-Control: no-store. Использовать стандартную библиотеку Go, таймаут и существующую защиту от межсайтовых запросов. Исключить секреты, токены и тела ответов из логов.
4. **Встроить виджет.** По кнопке загрузить WebSDK с официального CDN и открыть один экземпляр в кабинете. Callback истечения токена обращается к тому же серверному маршруту. При смене аккаунта или истечении сессии закрыть старый сценарий и предложить открыть кабинет заново. При ошибке сети показать возможность повторить. Документы передаются через виджет.
5. **Проверить.** Автотесты с имитацией API проверяют подпись, 401 для гостя, изоляцию двух аккаунтов, стабильность ID, обновление токена и ошибку провайдера. Отдельно пройти реальные шаги уровня с тестовыми материалами Sandbox, проверить обновление токена и отказ доступа к /meme до серверного одобрения. Зафиксировать результат прогона в state.md и sumsub.md.

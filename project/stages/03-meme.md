# Этап 3. Доступ к котику

**Статус: Черновик — ожидает согласования.** 26 ноября 2026. Реализация не начата.

## Результат и границы

На главной гость видит предложение зарегистрироваться и ссылку на вход; вошедший без одобрения — переход в кабинет; пользователь со статусом `approved` — мем. Прямая ссылка `/meme` также проверяет доступ. Sumsub, webhook, деплой и загрузка картинки через интерфейс в этот этап не входят.

## Картинка и технологии

Оставляем net/http, html/template и существующие auth/store; новых зависимостей и миграций БД нет.

Картинка — отдельный файл вне публичной статики, по умолчанию `app/resources/meme.jpg` при запуске из `app/`. Путь задаётся `MEME_PATH` (по умолчанию `resources/meme.jpg`); поддерживаем JPEG и PNG. Добавим временную картинку-заглушку и описание замены. Файл не встраивается через go:embed: сервер открывает его заново при каждом разрешённом запросе.

Чтобы сменить мем, достаточно заменить файл по тому же пути и обновить страницу — без сборки и перезапуска. Для замены во время работы сначала подготовить новый файл, затем переименовать поверх старого, чтобы запрос не прочитал недописанные байты. Изменение самого MEME_PATH требует перезапуска. Временный общий ресурс можно хранить в Git; свою локальную картинку — в игнорируемом `data/` с MEME_PATH. Постоянное хранение на хостинге определим на этапе деплоя.

## Доступ и ошибки

- GET/HEAD `/meme`: проверить текущую сессию и свежий статус из SQLite; только `approved` разрешает выдачу. ID пользователя из URL или формы не принимаем.
- Гость, истёкшая или отозванная сессия — 401; вошедший с любым другим статусом — 403; ошибка БД — 500.
- Файл открываем только после проверки доступа. Отсутствующий файл — 404, нечитаемый или неподдерживаемый файл — 500 без раскрытия пути. Проверяем тип содержимого, выставляем корректный Content-Type и `X-Content-Type-Options: nosniff`.
- `/meme` и персонализированная главная получают `Cache-Control: private, no-store`. Каталог ресурсов целиком через HTTP не публикуем. На главной у изображения есть alt-текст.
- Статус для локальной проверки задаём только в отдельной тестовой SQLite через SQL; публичный маршрут «одобрить себя» не добавляем. Инструкция будет в README.

## Приёмка

- Два пользователя с отдельными сессиями: только пользователь с `approved` получает картинку по одному и тому же URL. Гость, второй пользователь, просроченная сессия и запрос после выхода доступа не получают; HEAD защищён так же.
- Проверить три состояния главной, HTTP-коды, Content-Type, no-store, отсутствие публичной статики и обработку недоступного файла.
- Заменить картинку без перезапуска: следующий запрос получает новые байты. Отзыв статуса в БД закрывает доступ следующему запросу.
- Автотесты на временной БД и временных изображениях; ручная проверка в браузере. `go test -race ./...`, `go vet ./...`, сборка, `git diff --check`.

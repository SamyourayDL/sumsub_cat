## Как повторить

1. Проверить текущий Fly и webhook по [инструкции](../fly-operations.md).
2. Зарегистрировать три новых вымышленных аккаунта; открыть SDK в каждом.
   Остановиться до согласия/документов/камеры. Сверить новые ID в Sandbox Dashboard.
3. Из app/ загрузить доверенный .env в окружение подоболочки и вызвать
   `python3 scripts/sandbox-result.py APPLICANT_ID GREEN` (затем RETRY/FINAL
   для соответствующих отдельных applicant). Полная shell-команда — в README.
4. Проверить Sent/200 в Logs, кабинет и /meme, обновление/вход и restart с прежним томом.
5. В Logs нажать Resend у исходных applicantReviewed; проверить 200 и duplicate.
   Повторный testCompleted создаёт новое решение и не заменяет проверку повтора.

## Проверки и ограничения

Перед deploy: `go test -race -timeout 180s ./...`, `go vet ./...` — успешно.
Remote Docker build, config validate и deploy успешны. CLI фактически выполнен
с тремя исходами, `--help` проверен; `git diff --check` и ссылки проверены. CI нет.
Новых runtime-зависимостей нет; служебный CLI требует Python 3 и стандартную библиотеку.
Он использует фиксированный Sandbox-only метод, не следует redirects и не выводит
тела ответов или секреты. В приложении не добавлен маршрут смены статуса.

Б4 не выполнялась: нет загрузки документов, liveness, исправления документа через SDK
или проверки обновления SDK-токена. Согласие SDK не принималось. Этапы 5/6 целиком
остаются незавершёнными. Холодный старт проверен один раз, SLA не установлен.
Демо оставлено доступным с обычным autostop; остановка/удаление — отдельный запрос.

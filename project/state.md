# Текущее состояние · 26 ноября 2026

**Цель сдачи.** Проверяющий открывает развёрнутое приложение, создаёт аккаунт, проходит тестовый сценарий WebSDK и после обновления страницы видит актуальный статус.

**Готово — этапы 1–3.** Главная `/`, кабинет `/account`, health check `/healthz`; POST `/register`, `/login`, `/logout`. Гость регистрируется или входит; кабинет показывает собственный логин, статус «Проверка не начата» и выход. SQLite сохраняет аккаунты, статусы и сессии после перезапуска. Дубли нормализованного логина отклоняются. Мем доступен только с текущей сессией и статусом `approved`; Sumsub и деплой ещё не реализованы.

**Структура и версии.** Go module `sumsub-demo` в `app/`, Go 1.27.4. `internal/config` читает DB_PATH, MEME_PATH и COOKIE_SECURE; `internal/store` — SQLite schema v1, пользователи и сессии; `internal/auth` — bcrypt cost 12, случайные токены и сроки; `internal/web` — встроенные шаблоны и HTTP. Прямые зависимости: modernc.org/sqlite v1.63.0 и golang.org/x/crypto v0.59.0.

**Проверено.** Из `app/`: `go test -race ./...`, `go vet ./...`, `go build -o bin/server ./cmd/server`. Тесты проверяют валидацию и UTF-8, cookie обоих Secure-режимов, CSRF, методы, лимит тела, ошибки БД, атомарность, конкурентную регистрацию, изоляцию клиентов, отзыв и истечение сессии. После повторного открытия БД сохраняется также специально изменённый в тесте статус. В браузере на отдельной временной БД пройдено: регистрация → кабинет → выход → вход → остановка и запуск сервера → кабинет с прежней сессией. CI отсутствует.

**Как повторить.** Из `app/`: `DB_PATH=data/local-check.db COOKIE_SECURE=false go run ./cmd/server`, открыть http://localhost:8080/account. После регистрации остановить Ctrl+C, запустить той же командой, обновить страницу. Полный сценарий и команды — в [README](../README.md).

**Ограничения.** Сессия — 24 часа без продления. COOKIE_SECURE=false только для локального HTTP; при HTTPS установить true. `.env` автоматически не загружается. До публичного деплоя включить в подробный план защиту входа от перебора и ограничения нагрузки, в том числе bcrypt. Публичного изменения статуса нет. Пользовательские данные при тестировании не затрагивались.

# Проверка личности через Sumsub WebSDK

Веб-приложение на Go для демонстрации проверки личности. Пользователь создаёт
аккаунт, проходит проверку через Sumsub WebSDK и видит её результат в личном
кабинете. После одобрения на главной открывается котик.

[Открыть публичное демо](https://sumsub-cat-demo.fly.dev/account)

## Сценарий для проверяющего

1. Создайте аккаунт с тестовым логином и паролем. После регистрации откроется личный кабинет.
2. Нажмите **«Подтвердить личность»**. Демо использует Sumsub Sandbox,
   уровень `id-and-liveness` с проверкой документа и шагом Selfie.
3. Для успешного сценария возьмите документ из раздела Accepted. В виджете
   выберите страну и тип этого документа, загрузите нужные стороны с исходными
   именами файлов и пройдите шаг Selfie. [Официальные шаблоны Sumsub](https://docs.sumsub.com/docs/verification-document-templates#accepted-templates)
4. После отправки дождитесь результата в кабинете. При статусе
   **«Личность подтверждена»** нажмите **«Посмотреть котика»**. Доступ сохранится
   после выхода и повторного входа.

| Результат Sumsub | Что увидит пользователь |
| --- | --- |
| Approved (`GREEN`) | Кабинет подтверждает личность и даёт ссылку на главную с котиком. |
| Resubmission requested (`RETRY`) | В кабинете доступна кнопка «Исправить материалы». |
| Rejected (`FINAL`) | В кабинете отображается отказ, повторная подача недоступна. |

Чтобы увидеть RETRY или FINAL, используйте отдельные тестовые аккаунты и
шаблоны из разделов [Resubmission request](https://docs.sumsub.com/docs/verification-document-templates#resubmission-request)
и [Final rejection](https://docs.sumsub.com/docs/verification-document-templates#final-rejection).

## Как устроено

- Backend на Go выдаёт короткоживущий токен WebSDK для аккаунта из серверной
  сессии. Один аккаунт сохраняет один `externalUserId` для Sumsub.
- Виджет отправляет документы напрямую в Sumsub. Backend проверяет подпись
  webhook и сохраняет результат в SQLite. Кабинет отражает сохранённый статус.
- Сервер проверяет сессию и статус при каждом запросе к `/meme`. Гость
  получает `401`, вошедший пользователь без одобрения — `403`.
- Приложение работает на Fly.io. База SQLite хранится на постоянном томе
  отдельно от контейнера приложения.

## Что проверено

- В развёрнутом демо вручную пройдены Approved, Resubmission requested и
  Rejected с официальными документами и шагом Selfie. Статусы в Sumsub Dashboard
  совпали с ожидаемыми.
- Повторный вход сохранил доступ к котику у одобренного аккаунта. Доступ с
  неодобренных аккаунтов закрыт.
- На локальных тестах проверены привязка токена к сессии, обработка подписанных
  событий и их повторов, сохранение статуса и ограничения доступа.
- Обновление SDK-токена проверено локально с имитацией WebSDK. Живой прогон
  обновления и дополнительный сценарий повторной подачи после RETRY остаются
  открытыми.

## Локальный запуск

Требуется Go 1.27.4. Из корня репозитория:

```sh
cd app
go run ./cmd/server
```

Откройте [локальный кабинет](http://localhost:8080/account). Для регистрации,
входа и проверки сессий достаточно настроек по умолчанию. Для настоящего WebSDK
задайте настройки Sandbox в окружении процесса. Файл `.env` Go-сервер
автоматически не загружает.

| Переменная | Назначение |
| --- | --- |
| `SUMSUB_APP_TOKEN`, `SUMSUB_SECRET_KEY` | Серверные учётные данные Sandbox. |
| `SUMSUB_LEVEL_NAME` | Имя уровня в Sandbox. Демо использует `id-and-liveness`. |
| `SUMSUB_WEBHOOK_SECRET` | Секрет для проверки подписи Sumsub. Для доставки событий требуется публичный HTTPS-адрес с маршрутом `/webhooks/sumsub`. |
| `DB_PATH`, `MEME_PATH` | Пути к SQLite и JPEG. По умолчанию `data/app.db` и `resources/meme.jpg` относительно каталога запуска. |
| `COOKIE_SECURE` | `false` по умолчанию для локального HTTP, `true` на HTTPS. |
| `TRUST_FLY_PROXY` | `false` по умолчанию. `true` для запуска за Fly HTTP Proxy. |

Проверки из каталога `app/`. Для JavaScript-тестов нужен Node.js 18+.

```sh
go test -race -timeout 180s ./...
go vet ./...
node --test tests/verification.test.mjs
```
